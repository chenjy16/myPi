# P4-01 · 真实 E2E 场景清单（Phase 4 K4）

基准：`docs/V2-PHASE4-TASKS.md` P4-01 + `docs/V2-MVP-ACCEPTANCE.md` §3。范围限于**无审批可先跑**的场景（T4 / E / H）；订单/客户类场景需 Protected Customer Data 审批，容器演练需 Staging，均明确标注「待外部」。

## 环境前置（发布日一次性配置）

1. **Cloudflare 隧道**：沿用 Phase 3 的 prime-then-launch 策略——
   ```
   cloudflared tunnel --url http://localhost:8081
   ```
   复制隧道 URL，写进 `.env` 的 `SHOPIFY_APP_URL` 与 `shopify.app.toml` 的 `application_url`（本地临时改；不动 `automatically_update_urls_on_dev`）。
2. **shopify app dev**：`npm run dev`——CLI 起 web (8081) + worker，OAuth 回调经隧道回本地。
3. **登录 stepchic**：`https://stepchic.myshopify.com/admin`，浏览器进入 mypi 嵌入页。
4. **截图工具**：macOS 自带 Shift-CMD-5，输出到 `ui-forensics/`，命名见同目录 README。

## 场景 T4 · Low-stock → tags.add（demoable without confirmation wall）

| 步 | 操作 | 期望 | 截图 |
| --- | --- | --- | --- |
| T4.1 | Templates 页选 "Low stock → tag product" → 打开向导 | 阈值默认 5、tag 默认 `restock-soon`，「What it will do」三步预览齐 | `t4-01-wizard.png` |
| T4.2 | 点 Enable automation | 跳 My Automations 列表，行内 active 徽标 + v1 | `t4-02-enabled.png` |
| T4.3 | Shopify Admin → Products → 任选 SKU，Inventory → Available 改为 2 保存 | 5 秒内 webhooks/inventory_levels/update 到 `/webhooks/inventory_levels/update` | — |
| T4.4 | worker 日志看 `[ingest] accepted topic=inventory_levels/update` | WebhookDelivery 有行；ExecutionLog 有 `status=SUCCESS` 的一条 | `t4-03-triggered.png` |
| T4.5 | Activity 页展开该 execution | Step 1 · `tags.add` SUCCESS · target=Product gid；无 error | `t4-04-activity.png` |
| T4.6 | Shopify Admin → 该商品 → Tags | 显示 `restock-soon` | `t4-05-shopify-tag.png` |

**通过判据**：T4.4 中 `execution_awaiting_confirmation` **未**触发（tags.add 属 low risk）；`execution_succeeded` 触发一条；`/health` `automation.executionSuccess.rate === 1`。

| 步 | 操作 | 期望 | 截图 |

## 场景 H · 高风险动作确认前零 Mutation

| 步 | 操作 | 期望 | 截图 |
| --- | --- | --- | --- |
| H.1 | Templates 选一个含 `product.updateStatus` 的自动化（若模板未含，可手填 DSL 或用 T7 改造）；启用 | 详情页显示 high-risk 徽标 | `h-01-high-risk.png` |
| H.2 | 触发一次库存事件让引擎跑一遍 | ExecutionLog 一条 PARTIAL_SUCCESS；ExecutionStep 一条 `AWAITING_CONFIRMATION` | `h-02-await.png` |
| H.3 | **此刻检查 Shopify 端商品 status 未变**（应保持 ACTIVE/DRAFT 原样） | Shopify Admin 商品页 status 未改 | `h-03-before-confirm.png` |
| H.4 | Activity 详情 → 点 Confirm | 触发 `confirmStep` → admin.graphql 才发 mutation | — |
| H.5 | Shopify 端商品 status 变了；ExecutionStep 变 SUCCESS | 商品页 status 与 Automation 定义一致 | `h-04-after-confirm.png` |

**通过判据**：H.3 是关键——**未确认前零 Mutation**。这条与 `tests/automation-engine.test.ts` 「路径 C」的断言互为镜像：测试证明「引擎不发」，H.3 证明「Shopify 端也没变」。埋点 `execution_awaiting_confirmation` 记一条。
